### Starter

Работает локально: повторный запуск отдельным процессом занял ~0,38 с, exit 0. Он создаёт 2248 строк nodes_roles, но все роли/evidence пусты; clusters и top_nodes без строк. Это шаблон, не готовое решение.

Оставляем/адаптируем:
- `load`: загрузка parquet, преобразование даты;
- `basic_features`: степени, наблюдаемые обороты/число переводов, PageRank, флаг границы;
- схемы трёх CSV, CLI `--data`/`--out`, словарь шести ролей.

Исправляем:
- `sanity_check` сверяет только наличие пар, хотя печатает совпадение edges/transactions. Добавить суммы, counts, типы, null, уникальность, ссылки gid, допустимые значения.
- `build_graph` не добавляет изолированные узлы. Сначала `add_nodes_from(nodes.gid)`, затем рёбра.
- `pass_through` — отношение наблюдаемых потоков, не баланс; не использовать как полноценный баланс seed и не делать вывод о полном балансе остальных.
- отсутствие измерения времени, полноценной кластеризации, ролей, приоритетов, объяснений, UI, AI и тестов.

Зависимости starter: pandas, pyarrow, networkx, numpy. PageRank в текущем NetworkX использует scipy; включить её явно. Локально уже установлены pandas 3.0.6, numpy 2.5.3, pyarrow 25.0.1, networkx 3.6.1, scipy 1.18.1, FastAPI 0.141.1, uvicorn 0.53.0, openai 3.16.2. Наличие пакетов не заменяет чистую установку по итоговому requirements.

Пишем конкурсное решение в официальном репозитории. Из тренировочного проекта основной код не копируем. Библиотеку графа хранить локально с лицензией, не зависеть от CDN при демонстрации.

## Архитектурные решения

**CORE.** Направленный взвешенный граф со всеми узлами; признаки суммы/числа/степени раздельно; достижимость от разных seed — обходами с множеством visited, не перебором всех путей. Это не независимость и не доказательство фактического происхождения денег. Louvain на явно задокументированной неориентированной проекции; встречные суммы складывать. Стабильный порядок узлов и seed для воспроизводимости. Не задавать сумму ребра как расстояние для betweenness: выбрать ненагруженное кратчайшее расстояние и описать смысл, либо отложить метрику.

Для ролей считать детерминированные силы признаков и выбирать основную по раскрытому правилу. Сохранять альтернативы и противоречия во внутреннем JSON. `role_score` оставить в обязательном CSV: нормализованная сила наблюдаемых признаков роли, не калиброванная вероятность. `terminal` не назначать только за out_degree=0, особенно depth=4. `coordinator` обозначает структурную гипотезу, не доказанного организатора. `peripheral` — недостаточно признаков по правилам, не доказательство отсутствия риска.

**ADVANCED.** Уровни HIGH/MEDIUM/LOW — относительная пригодность данных для конкретных выводов внутри ограниченной выгрузки, не полнота банковской истории. LOW на границе/при изоляции; seed получает ограничение входящего потока. Для каждого уровня показывать причины. Приоритет не умножать на наблюдаемость: структурно важный узел с низкой наблюдаемостью попадает в REQUEST MORE DATA. Очередь INVESTIGATE NOW требует сильных признаков и достаточной наблюдаемости, остальные MONITOR / LOWER PRIORITY. Изолированный seed не объявлять безопасным: недостаточно транзакционных данных; приоритет здесь только по структуре.

Temporal: сопоставление сумм без повторного расходования входящего объёма, окно 1–2 дня. Основной консервативный расчёт допускает только строго более позднюю дату; внутридневные совпадения выделяются как неопределённые, не устанавливают порядок. Не списывать исходящие из будущих входящих. Не называть результат отслеживанием конкретных денег, не вычислять точное время удержания в часах. Проверить влияние границ месяца и нехватки наблюдаемого входа.

**UI.** Три очереди, топ-лист, поиск всех gid, направленное соседство и обзор сообществ, карточка с факторами score, альтернативами и ограничениями. Все 2248 доступны; по умолчанию не рисовать 2248 подписей одновременно. CSV скачиваются из вычисленного результата.

**AI.** OpenAI вызывается сервером. Read-only tools: get_node_metrics, compare_nodes, get_neighbors, get_seed_reach, get_temporal_evidence, get_data_gaps. Ограничить число шагов/объём ответа. Числа брать из tools; ссылки на gid/факты проверять, неизвестные ссылки не показывать как доказанные. Запрос дополнительных данных — рекомендация, а не скрытое получение извне. Основные CSV и UI работают без API; при сбое честный статус, без имитации LLM. Ключ не нужен для обязательного расчёта и не отправляется браузеру.

## E. Риски и проверки

- **Денежные значения:** для сопоставления и равенств переводить в тиыны с явным округлением; сейчас суммы float64. Не требовать точного float-равенства.
- **97 одинаковых строк:** сохранить, поскольку нет уникального ID и они входят в агрегаты. Автодедупликация испортит сверку.
- **Нет ground truth:** не обещать accuracy. Проверять соблюдение правил, известные малые графы, инварианты, устойчивость только если реально измерена.
- **Наблюдаемость:** нельзя устранить неполноту математикой; сильное предупреждение при depth=4 и для внешних/входящих данных.
- **Стабильность кластеров:** фиксированного seed достаточно для воспроизведения, но не для заявления о статистической устойчивости.
- **Производительность:** исключить all_simple_paths/неограниченный simple_cycles. Основной расчёт локально; LLM не вызывать по одному разу на каждый из 2248 узлов.
- **Развёртывание:** локальные пакеты уже есть, но нужно тестировать новый venv. Зафиксировать проверенные зависимости, инструкцию установки и резерв без LLM.
- **Данные предназначены только для хакатона:** не публиковать их на внешних демо-сервисах; соблюдать выданный репозиторий и область использования. Источник starter указать отдельно.
- **Новые ключи/сервисы:** не менять существующий .env; не выводить его содержимое. Проверка OpenAI-запроса и доступности модели относится к этапу AI, пока не выполнялась.

## H. Что сокращаем первым

1. Удаление узлов/анимация последствий, циклы, независимые пути, Monte Carlo устойчивость — за пределами базового scope.
2. Визуальная полировка и богатый общий граф; сохраняем направленные связи, поиск и карточку.
3. Широкий чат с произвольными запросами; оставляем 3–4 проверяемых сценария AI-tools.
4. При жёстком дефиците времени — сложный temporal matching, оставляя честные базовые признаки и ограничения (это optional).

Не сокращаем: обязательные схемы/строки/роли/кластеры/top ≥20, объяснение любого gid, ограничения вывода, воспроизводимый запуск, README и проверку <5 минут. Новые идеи не добавляем.
