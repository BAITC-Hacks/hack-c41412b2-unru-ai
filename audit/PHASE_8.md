# PHASE 8 — Pattern Analysis

2026-09-23. Продолжение разработки прямо разрешено участником после предыдущего feature freeze. Сдача на платформе по-прежнему отложена по его просьбе.

## Реализовано

Один локальный модуль `moneygraph.patterns`, отдельный `outputs/patterns.json`, три раскрываемых секции карточки. Детерминированные расчёты без новых зависимостей или внешних данных. Основной pipeline и формулы не менялись.

- Temporal: max-flow в integer tiyn между дневными bucket при +1/+2 дня; исключение поздних входов без полного календарного окна; same-day отдельно ORDER UNKNOWN; gather→scatter; правило всплеска.
- Routes: повторяющиеся пары дней A→B→C, взаимные связи, направленные циклы 3–4 с лимитом поиска. Полные GID и подсветка видимой части маршрута.
- Peer anomalies: средние ранги внутри depth, минимальный размер группы 20, порог ≥99-го процентиля; наблюдаемое распределение равных сумм нескольким получателям.

## Ограничения

Совместимый max-flow — верхняя граница возможного согласования сумм, не
прослеживание средств. Календарное окно не означает полноту банковских
наблюдений. Gather→scatter окна и разные цепочки могут разделять операции.
Циклы имеют только структурную, не подтверждённую временную направленность.
Peer-группа — тот же depth в выборке, не контрольная группа населения.
Равные суммы не доказывают дробление; подпороговые переводы отсутствуют.
Нет ML-обучения, оценки accuracy, disjoint paths или внешних атрибутов.
Все правила и ограничения записаны в README; новые факты не передаются AI.
